# 三章小说流程验收基线（1.1，2026-09-23）

历史仿真见 report.md，不改写历史结果。本基线用于新版协议测试。
自动化测试中的人工输入与审批仅是明确标记的夹具；真实执行必须等待用户。

## 定义

- 大纲 task 产出实际三项章节数组，Schema 限定长度3；不能用自报 chapter_count
  或恒真 gate 替代完备性检查。
- foreach 按 item 分配章节身份；前章 exports 显式作为 previous 材料。
- 每章800-1200汉字、关键事件与大纲一致；文件外置，单次结果≤2000字符。
- task.check 有具体 criteria 和 max_attempts，质检结果包含 verdict 与 reason。
- 大纲人工验收、最终成书人工验收保留；通用小说案例另保留逐章人工验收。
- 不数目录、不手写章节循环回边、不添加空定稿节点；最后任务自然结束。
- 文件写入 run.dir，重复启动不覆盖旧运行产物。

## 协议验收

1. 根 run 始终返回可执行叶子动作；无需手动完成 start/end 或切换 child。
2. 第一章首稿质检 REVISE，明确缺陷；第二稿 PASS，身份与产物路径相同。
3. 进入第二章 previous_output 为空，previous 材料包含第一章已通过产物。
4. 质检到上限必须失败；resume 不可绕过；人工 review 不可用 complete 跳过。
5. 重放旧 action.id 被拒；current 不写磁盘。
6. 嵌套失败可从根 resume；动态清单等待新增，done=true 才结束。
7. 输出文件不存在、路径不符、Schema错误均驳回；漏字段不得静默变空串。
8. 最终 completed，清单三项success，章节顺序和产物索引完整。

## 验证分层

- 引擎/CLI夹具验证协议和数据契约，不声称证明小说文笔、剧情质量或Agent成功率。
- 真实创作验证须实际读正文、工具统计汉字、审查事件与连续性，并记录人工结论。
- 无上下文Agent接管/创建能力需单独实验；未执行时明确标为未测，不编造节省比例。
